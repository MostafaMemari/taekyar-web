### Key findings
- **Brand split:** public site primary is `#e0282e` (red, `.dark` palette); dashboard uses
  `#2563eb` (generic Tailwind blue). A commented-out `.theme-light` block in `app/globals.css`
  (lines 134-152) shows the dashboard originally used the red brand.
- **Theme leak:** `<html class="dark">` + `AppBackground` fixed `theme-light` div + dashboard
  wrapper `theme-light`. `dark:` utilities still fire inside the admin (e.g. `Button variant="outline"`
  gets `dark:border-input dark:bg-input/30`). No dashboard file uses `dark:` explicitly.
- **globals.css is a graveyard:** 3 commented-out theme blocks; `--chart-1..5` and `--sidebar-*`
  only exist in commented code (undefined at runtime); `:root` and `.dark` define conflicting palettes;
  scrollbar/`::selection` hardcode blue.
- **IA:** `data/dashboard/navigation.ts` = 10 flat items under one "مدیریت محتوا" heading, mixing
  content / taxonomy / engagement / system. No pending-comment badge. No breadcrumbs.
- **Bug:** `dashboard-mobile-nav.tsx` renders `<DashboardSidebar username={username} />` without
  `siteName`/`logoImage` props → brand logo lost in the mobile drawer.
- **Bug:** desktop sidebar wrapper uses `overflow-hidden` with `lg:h-screen` → nav can clip with no scroll.
- **Dead decoration:** overview stat cards have an empty `opacity-[0.035]` overlay div, `border-t-[3px]`
  tint, and a meaningless "بهروز"/"نیاز به بررسی" badge; hover shadows on non-interactive cards.
- **No charts** and no chart lib installed; overview is 4 KPI cards + 2 queues.
- **States:** no `app/dashboard/error.tsx`; `loading.tsx` exists only for categories, comments, media,
  posts, tags (missing: overview, pages, menus, faqs, settings, trash, new/edit).
- **Dup duplication:** page-header markup copy-pasted across 8+ pages with drifting sizes
  (`text-[22px] font-black` vs `text-xl font-black` in faqs). Heavy arbitrary values
  (`text-[13px]`, `h-10`, `rounded-xl`) instead of a type/space scale. `font-black` used for
  h1 + card titles + stat numbers + badges + usernames → flat hierarchy.
- **A11y:** no skip link, no `scope="col"` on table headers, no `aria-busy` on pending submits,
  icon buttons 32px (below 44px), low-contrast `muted-foreground/60`+ placeholders and 10px badges.

## Dashboard redesign implemented ("Dojo discipline")

Approved direction: primary `#e0282e`, near-white surfaces, crisp 1px borders, 8px rhythm, one accent,
belt colors only for rank/status, no gradients/glow/emoji, Lucide + Vazirmatn. Presentation only —
no Prisma/DB/auth/session/server-action/business-logic changes; no public-site changes.

### Theme isolation (the core mechanism)
- `app/globals.css`: `@custom-variant dark (&:is(.dark *):not(:where(.theme-admin, .theme-admin *)));`
  so `dark:` utilities stop leaking into the admin while `<html class="dark">` stays for the public site.
- New `.theme-admin` scope (declared AFTER `.theme-light` so it wins at equal specificity) with
  `color-scheme: light`, `--primary: #e0282e`, plus new `--success*`, `--warning*`, `--info*`,
  `--chart-1..5`, `--surface`, `--surface-muted` tokens registered in `@theme inline`.
- **Gotcha:** Radix portals escape the dashboard DOM, and `components/ui/{dialog,select,dropdown-menu}.tsx`
  bake `theme-light` into their content. Every dashboard portal consumer must append `theme-admin`
  (confirm-dialog, menu-manager, taxonomy-form, robots-fields, media-picker, post-faq-editor, faq-dialog,
  command menu, user menu, topbar sheet, media sheet) — otherwise dialogs/selects render blue `theme-light`.
